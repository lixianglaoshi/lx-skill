# lx 学科可视化

把学生“看不见、摸不着”的关系，做成可操作、可预测、可验证、可解释的教学页面。交付物默认是用户工作目录中的一个可直接打开的 `.html`，而不是一段孤立的代码或一张静态图。

## 与相邻 LX Skills 的分工

本 Skill 优先处理“一个学科关系或具体题目，要做成可验证的互动页面”，尤其是结果必须精确一致的数学与化学任务。

| 用户真正要的结果 | 优先 Skill | 判断要点 |
| --- | --- | --- |
| 任务、关卡、角色、段位、奖励或整节游戏化课 | `lx-gamified-learning-design` | 先设计学习机制，不先写网页 |
| 函数、图像、数据、流程、具体题目或需精确计算的几何/化学 | **lx-subject-visualization** | 交付互动页面；公式、图形、答案同源 |
| 齿轮、传动、空间装配、剖切、力与运动等动态 3D 过程 | `lx-3d-teaching-animation` | 学生必须通过旋转、暂停、分步看清过程 |

冲突时遵守两条优先级：

- “能旋转的立体几何**解题**网页”先选本 Skill，因为题面、坐标、答案和推导必须精确；可再调用 3D Skill 补充动态展示。
- “把观察物体做成《我的世界》式**学习游戏**”先选游戏化 Skill，因为先要确定搭建、投影、预测、验证与迁移的教学机制。

## 先选对模式

先阅读用户已经提供的题目、教材页、图片、教案和学情，不重复索要已有信息。只有缺少会改变设计判断的内容时，第一轮最多问三个问题：学习者年龄/阶段、要理解或解决的关系、可用设备与使用场景。

| 用户目标 | 使用模式 | 必须让学生操控/看见什么 |
| --- | --- | --- |
| 任意学科主题、初中函数、物理现象、统计/流程、生物等 | **通用互动页面** | 参数、对象、图像、过程或证据之间的关系 |
| 高中立体几何题 | **立体几何精确解题** | 3D 几何体、关键线/面、镜头、分步向量关系 |
| 高中解析几何、圆锥曲线题 | **解析几何精确解题** | 曲线、动直线/动点、参数滑块、范围或不变量 |
| 初高中化学反应、配平、氧化还原或反应机理 | **化学反应精确演示** | 原子守恒、断键/成键、电子或能量变化 |

如果用户要先设计整堂课的游戏机制、段位或关卡，而非生成一个具体网页，转交 `lx-gamified-learning-design`；确定需要哪一个可视化网页后再回到本 Skill。

## 共用教学底线

1. 先写清学习目标和学生应完成的认知动作，例如拖动、旋转、预测、比较、解释、验证、修正；“点对答案”不算核心动作。
2. 每个关键操作必须有可理解的即时反馈：改变了什么、这说明哪个关系、下一次还能改哪个变量。
3. 页面至少包含：问题/现象、一个核心可操作模型、引导性解释、一个预测或验证任务，以及把结果迁移到纸笔表达、公式或新情境的出口。
4. 选择最简单足够的媒介：函数、坐标、图表和证明优先 SVG/Canvas；精确立体几何仅在题目需要时使用轻量 3D 辅助。若核心是部件运动、传动、剖切或空间过程，转用 `lx-3d-teaching-animation`。不要为了“看起来高级”强行加 3D、粒子或测验。
5. 默认兼容投影/希沃白板和少量电脑；把“教师大屏演示、学生预测—记录—解释”的流程设计进页面，不假定每人有设备。
6. 不使用真实学生姓名、头像、成绩或班级排名。化学页面只用于概念与微观可视化，不给出危险实验的操作细节。

## 通用互动页面

适用于没有被下方三种精确模块覆盖的主题，也适用于初中函数。

先确定一个“可视化核心对象”，例如：函数的参数与曲线、力与运动轨迹、细胞结构与物质流动、统计数据与分布、历史事件的因果链。再确定学生能改变的 1—3 个变量，不能把所有内容塞进一个控制台。

生成单文件 HTML 时：

- 使用中文界面并跟随用户语言；移动端与大屏均可操作。
- 采用模块化但内联的 CSS/JS；允许按需引用稳定 CDN 的 Three.js、KaTeX 或 D3，但不得依赖本地服务器、构建步骤或私有 API。
- 用滑块、拖拽、视角旋转、播放/暂停、重置或随机样例中的必要项服务于学习，不机械堆满控件。
- 若有公式，用 KaTeX；若有小测验，必须可折叠，且先让学生操作和解释再显示检验。
- 输出前自行核对：初始状态可读、每个控件真的改变模型、重置有效、图像/公式/标注同步、没有明显控制台错误。

如用户要求“只给我可直接投喂给编程 Agent 的提示词”，先交付清晰的教学机制和验收条件，再生成提示词；不得把原始第三方作者、产品名、账号或视觉风格说成 LX 独创。

## 三种精确模块

这三个模块已完整收录在 `vendor/edulab/`。用户请求落入其范围时，先读取对应模块中的 `SKILL.md`、`references/`，然后严格按其计算与生成流程执行。

### 立体几何

路径：`vendor/edulab/edu-solid-geometry/`

- 从文字、图片确认后的题面或随机题整理结构化问题。
- 运行 `lib/geometry_kernel.py` 获取精确坐标、向量、法向量和答案；不得凭心算填数。
- 用 `scripts/generate.py` 与 `template/lesson.html` 生成交互 HTML。模型坐标必须来自同一计算核心。
- 交付前检查答案卡、末步公式和 3D 高亮所指对象一致。

### 解析几何 / 圆锥曲线

路径：`vendor/edulab/edu-analytic-geometry/`

- 先确认题面中的曲线、条件、所求和语言；图片题必须回显识别结果请用户确认。
- 用 `lib/analytic_kernel.py`、`lib/conics.py` 精确计算；范围题尤其检查端点是可取还是仅为极限。
- 用 `scripts/generate.py` 与 `template/board.html` 生成页面；滑块读数、动态画板、范围条和最终答案必须同源。
- 不把“拖动到了一个数”当作证明；页面要保留可展开的推导和迁移提问。

### 化学反应微观演示

路径：`vendor/edulab/edu-chem-reaction/`

- 确认反应物、产物、条件、反应类型和语言；图片方程先回显确认。
- 用 `lib/reaction_kernel.py` 自动配平、检查原子守恒与原子映射，并从反应前后差异推导断键/成键。
- 用 `scripts/generate.py` 与 `template/reaction.html` 生成页面；根据反应选择 `morph`（守恒与重组）或 `mechanism`（机理关键帧）。
- 交付前核对配平系数、方程、分子个数、守恒计数器和动画数据一致；若 RDKit 未安装，使用内置分子几何，不自动安装任何依赖。

## 依赖、文件与验证

精确模块依赖 `sympy`。先检查当前解释器能否 `import sympy`；缺少时说明情况并征求用户同意后才安装或切换解释器。不得自行安装 `sympy`、RDKit 或任何其他包。

把最终 HTML 写到用户当前工作目录或用户指定路径；临时构建脚本、预览截图、缓存和本地服务不得留在成品目录。若启动预览服务，检查完立即关闭。

完成前至少验证：

- 题目解析、答案、公式、模型/动画来自同一数据源；
- 生成的 HTML 能在浏览器直接打开；
- 交互与教师提问确实指向目标概念，而不是只增加视觉刺激；
- 若来源是图片，已声明图像识别可能出错，并取得题面确认。
