# 李翔老师游戏化教学案例抽象

> 本文件只记录用户亲自提供的案例抽象，不把媒体报道中的细节当作已验证课堂事实。正式公开发布前，应由用户核对案例名称、课次、截图和数据。

## 案例一：四年级下册“观察物体（二）”——建造、图纸与视角

### 已知课堂事实

- 学段：小学四年级；用户回忆为人教版数学四年级下册“观察物体（二）”。公开教材目录也将该内容列为四年级下册第二单元，但不同版本教材仍应以学校实际使用版本为准。
- 学生困难：空间想象能力有限，仅靠静态图片或教师讲解难以稳定建立不同方向的空间表象。
- 游戏机制：借鉴《我的世界》的方块搭建，把立体物体变成可以建造、旋转、拆分和观察的对象。
- 操作方式：学生在电脑上操作，教师在讲台或希沃白板上演示；游戏中有图纸，也允许自定义题目。教师可以先自由搭建一个立体物体出题，也可以让学生按图纸顺序搭建，再进入观察与作图。
- 学习结果：学生能够从不同方向描述物体形状，依据图纸搭建立体结构，把不同方向看到的形状画在纸上，并通过演示或“拍一拍”类课堂互动表达观察结果。
- 现实限制：乡村小学不一定能做到每名学生一台平板或 iPad，设计不能假设一人一设备。
- 教师回顾中仍待补证：小组人数、具体关卡、学生最常见错误、哪些环节未达到预期，以及游戏与纸笔迁移之间的具体证据。

### 截图中可确认的界面证据

截图显示一个“第一关：经典T型（人教版典型）”的教师出题/验证界面，包含：

- 教师自由画图出题入口；
- “正（前）”“左（左）”“俯（上）”三个方向的网格投影区，绿色方块表示从对应方向看到的形状；
- “提交验证”“答案演示”“清空”三个课堂操作；
- 中央三维方块搭建场景；
- 视角切换：看正视图、看左视图、看俯视图、切回漫游；
- 方块操作：放置、挖掉、起飞、下降、加速，以及键盘 W/A/S/D 漫游；
- 大屏端可直接在空白处拖动画布，PC 端点击锁定鼠标操作。

这些界面说明它具备“立体操作 → 三视图投影 → 纸上表达 → 提交验证 → 答案演示”的完整链路，而不只是选择题。

### 可迁移的设计模式

1. 先让学生搭建和旋转，再要求学生说出“从哪里看见什么”。
2. 把图纸、立体结构、视角投影和纸笔表达放在同一个闭环中。
3. 同一关卡同时准备：教师大屏演示版、小组轮流操作版、实物方块/纸片降级版。
4. 评价“预测—操作—验证—解释”的过程，不只评价图形是否画对。
5. 把“从哪个方向开始”设计成显性策略：先定位观察者位置，再选择正/左/俯视图，最后把可见方块投影到网格。
6. 让学生经历“自由搭建出题”和“按图纸还原”两种方向，比较出题者与观察者的不同任务。

### 建议的完整关卡顺序

以下顺序根据截图和用户描述整理，正式复刻时仍应由教师按原游戏核对：

1. **自由漫游与放置**：熟悉起飞、下降、加速、视角和放置/挖掉，不考察数学答案。
2. **按图纸搭建**：根据图纸从底层到上层、从基准位置到外延位置逐步搭建；每一步保留撤销或回看。
3. **三视图预测**：暂停漫游，先在正、左、俯三个网格上画出预测，再切换视角验证。
4. **方向策略**：给出同一立体物体，要求学生先说“我从哪里看、为什么先看这一面”，再完成投影。
5. **反向建造**：只给三视图或部分图纸，让学生搭出一个符合条件的立体结构，并说明是否存在多个答案。
6. **自定义出题与互评**：教师或学生搭建结构，另一组根据三视图还原并解释；评价过程和理由，不只评价最终模型。

### 最常见错误与教学提示

- **不知道从哪个方向开始**：提示学生先找观察者位置和基准面，不直接告诉“看正面”。
- **把三视图当成三张独立图片**：用同一方块高亮对应位置，让学生看见三个投影来自同一空间结构。
- **只看最高层，不看遮挡/深度**：允许切换视角、挖掉或分层显示，比较“看见的面”和“模型中实际存在的方块”。
- **会搭但不能画**：在游戏里暂停，让学生把当前视角投影到纸上，再与网格自动叠加核对。
- **画对但不会解释**：要求学生指出一个方块从哪一面可见、它在网格中对应哪一格。
- **操作很熟但概念没有迁移**：更换方块数量、朝向、遮挡和图纸格式，观察能否重新预测。

### 设备有限时的课堂编排

- 教师端：大屏展示三维场景，教师负责搭建或邀请一名学生操作。
- 小组端：每组一台电脑时，分配“搭建者、视角记录者、作图者、解释者”，每关轮换。
- 无设备端：用立方体积木搭建，三张方向网格贴在黑板上，用手电筒/观察框模拟视角，纸上完成投影。
- 全班验证：先让各组举牌或在纸上作图，再由教师切换正/左/俯视图统一核对，避免只有一个学生操作、其他学生观看。

## 案例二：除法竖式——老板分糖与公平分配

### 已知课堂事实

- 用户将除法或除法竖式设计为“老板分糖”：除号内部或中心区域表现为老板的糖，外部对象表现为需要分到糖的孩子。
- 学生通过拖动、分配和观察，理解“总数、平均分给几份、每份多少、余下多少”的关系。

### 可迁移的设计模式

1. 先用可拖动的糖或物品完成平均分，再逐步显示除法算式。
2. 把竖式中的每一行对应到一次分配、回收或剩余变化。
3. 学生必须解释“这一位为什么这样写”，而不是只拖到正确答案。
4. 通过改变总数、份数和是否有余数，检查学生能否迁移分配结构。

## 案例二的扩展：从操作到竖式

“老板分糖”不能停在把糖拖给孩子。完整的递进应是：

1. 学生先把糖平均分给若干孩子，允许出现分不完的情况。
2. 系统显示每轮分了多少、还剩多少、每个孩子已有多少。
3. 学生把一次次分配压缩成横式、竖式或语言步骤。
4. 系统故意提供一个错误分配，让学生通过剩余糖果和总量关系找错。
5. 改变总糖数、孩子人数和余数，要求学生预测后再操作验证。

## 案例三：学习段位与班级运行——进阶反馈而非公开排名

### 已知课堂事实

- 用户借鉴《和平精英》的青铜、白银、黄金、铂金、钻石、王牌、超级王牌、无敌战神等段位意象，把一个学期或单元视为逐步上分的学习进阶。
- 完成练习册、基础训练和教师规定任务可获得进阶；自主完成任务、课堂投入和高质量表达可以获得更高等级评价，例如 3S 级评价。
- 课堂睡觉、消极参与等行为会被转化为较轻松的游戏化称号或扣分提醒；学习表现好的学生可以获得“大手子”等荣誉称号。
- 段位领先、荣誉和自主选座位等机制，也承担班级管理和持续反馈功能。
- 用户补充：可把一个单元理解为获得若干颗星，把练习册、基础训练、自主完成任务和课堂表现转化为上分过程；高质量自主完成可获得 3S 级评价，称号和荣誉用于表达学习投入与贡献。

### 必须保留的教育边界

1. 段位应表示个人掌握和投入的阶段，不应把学生公开羞辱或固定排名。
2. 称号应描述可改变的行为或贡献，不应变成“聪明/笨/差生”等人格标签。
3. “上分”不能只等于刷题数量；应包含自主完成、解释、帮助同伴、修正错误和迁移应用。
4. 扣分机制要可修复、可申诉、可回到学习任务，不能把一次睡觉或失误永久记录为身份。
5. 自主选座位等奖励需考虑视力、特殊需要、同伴关系和班级公平。

### 把段位机制拆成三本账

- **掌握账**：能否独立完成、解释、纠错和迁移知识。
- **行动账**：是否按时开始、持续尝试、主动修正和完成约定任务。
- **贡献账**：是否表达思路、帮助同伴、承担小组角色、维护学习环境。

段位升级应由三本账的可观察证据综合决定，不能只由题量或单次考试决定。对外展示时优先展示个人成长路径和小组合作，不公开学生之间的固定高低。

## 案例四：现实购物应用题——从文字题到可交互情境

### 已知课堂事实

- 用户会把应用题转成现实场景，例如买东西。
- 学生可以拖动商品、选择数量、付款或比较方案，把文字中的数量关系变成可操作对象。

### 可迁移的设计模式

- 先让学生完成真实决策，再让学生解释使用了什么数量关系。
- 同一场景中保留多种可行策略，要求比较而非只找标准答案。
- 之后再把操作压缩成线段图、算式、表格或文字表达。

## 案例五：沏茶问题——时间轴与并行安排

### 已知课堂事实

- 用户曾在中国教育电视台展示“沏茶问题”的可视化设计。
- 游戏或课堂活动使用可拖动时间轴，把烧水、洗茶杯、找茶叶、沏茶等步骤放到时间线上，观察哪些任务可以并行、哪些任务存在先后依赖。
- 用户强调，这类设计的价值在于让学生“拖动并看见时间关系”，而不是把最短时间当作唯一答案。

### 可迁移的设计模式

1. 先把任务卡拖到时间轴，允许学生试错。
2. 用颜色或连线表示前置条件和并行关系。
3. 学生解释“为什么总时间减少/没有减少”，再记录优化后的流程。
4. 改变任务时长或前置条件，检查学生能否迁移安排策略。

## 本案例库的使用边界

- 这些案例用于抽象设计机制，不代表所有班级都能复制相同效果。
- 媒体报道可以作为背景线索，不能代替用户的课堂记录、学生作品和学情证据。
- 任何具体教材册次、节目名称、学生成绩变化和效果数据，公开发布前必须由用户确认。
