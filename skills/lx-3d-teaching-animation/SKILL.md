# lx 3D 教学演示动画

把空间、运动、结构和过程做成学生可以暂停、旋转、拆开、预测和解释的 3D 教学演示。默认成品是用户当前工作目录中的可直接打开网页，而不是一段孤立代码、一个只可观看的视频，或一页答题器。

## 先判断 3D 是否真的必要

3D 只解决二维图难以表达的关系：遮挡、前后、内外、空间方位、部件连接、运动链、受力/能量流、微观结构或随时间变化的过程。

- 若核心是函数、图表、平面坐标、统计关系，优先使用 `lx-interactive-teaching-generator` 的 2D 互动页面，不为“高级感”强加 3D。
- 若核心是严谨的高中立体几何、解析几何或化学反应精确计算，转用 `lx-highschool-geometry-chemistry` 对应的精确模块；本 Skill 可以为其结果补充空间演示。
- 若用户要设计整节课的游戏任务、关卡、积分或班级运行机制，转用 `lx-gamified-learning-design`；确定某一个要演示的对象后再回来。

## 与相邻 LX Skills 的优先级

本 Skill 优先处理“对象在空间中怎样构成、怎样运动、怎样传递或怎样变化”。关键词通常是三维、旋转、拆开、剖切、内部结构、传动、受力、运动方向、逐帧/时间轴和演示动画。

| 用户真正要的结果 | 优先 Skill | 例子 |
| --- | --- | --- |
| 完整游戏机制、关卡与学习反馈 | `lx-gamified-learning-design` | “把观察物体做成建造闯关游戏” |
| 函数/图像的互动单页 | `lx-interactive-teaching-generator` | “做一个能拖动斜率的函数网页” |
| 高中题目求解、精确公式或化学配平 | `lx-highschool-geometry-chemistry` | “解正方体线面角题并保证答案正确” |
| 可旋转、暂停、分步观察的动态空间/运动过程 | **lx-3d-teaching-animation** | “为什么两个啮合齿轮转向相反” |

“能旋转的立体几何解题网页”仍优先 `lx-highschool-geometry-chemistry`，因为精确题解优先于动画；当公式与答案已经确定、但学生仍需理解空间关系时，再用本 Skill 补一段 3D 演示。

## 先弄清要学生学会什么

先阅读用户已提供的题目、教材页、图片、教案与学情，不重复询问。缺少会改变设计判断的信息时，第一轮最多问三个问题：

1. 学段、学科和这一段课最想让学生理解的关系是什么？
2. 学生最容易在哪一步看错、想错或说不清？
3. 教师会在希沃/投影大屏演示、学生小组轮流操作，还是每人能操作？

用户若已经明确要求直接制作，应作出合理假设并在交付前列出，不要以提问拖延。若是图片题或结构图，先用自己的话回显识别到的对象、标注和任务，请用户确认后再把它当作精确依据。

## 设计一个真正教学的动画

先写一个简短的“学习动作链”，再写代码。每一段应回答：学生看什么、能改变什么、预期会发现什么、如何证明自己理解了。

一个合格的 3D 页面至少有：

1. **问题入口**：真实情境、结构图或预测题，先让学生说出猜想。
2. **可操控模型**：旋转、缩放、播放/暂停、分步、重置，以及确实必要的剖切、透明、爆炸视图、参数滑块或镜头预设。
3. **可读的因果表达**：运动、箭头、颜色、标签和字幕说明“哪个部件/量变化，为什么引起下一个变化”。颜色不能单独承担意义。
4. **停顿与验证**：在关键帧暂停，要求学生预测下一状态、寻找对应部件或解释理由；之后再显示/播放验证。
5. **迁移出口**：回到纸笔图、公式、口头描述、实物操作或新情境，检验学生能否离开动画仍说清关系。

不要把复杂动画当答案展示。对于如齿轮传动、杠杆、滑轮、发动机、人体器官、立体几何等主题，优先显性呈现输入、传递路径、方向/比例变化和输出；允许学生逐段观察，而不是全程自动播放。

详细的镜头与课堂脚本模板见 [references/teaching-storyboard.md](references/teaching-storyboard.md)。

## 生成网页的技术要求

默认用单个 HTML 文件交付，CSS 与 JavaScript 内联；必要时使用稳定 CDN 引入 Three.js。页面必须能直接双击打开，不依赖本地服务器、构建流程、私有 API 或教师账号。

- 优先用基础几何体和程序化材质创建原创模型；只有用户明确提供并允许使用的素材才可嵌入外部模型。
- 用一个共享状态源驱动模型变换、标签、时间轴、数值读数和文字说明，避免“动画动了但解释没变”或控件彼此矛盾。
- 交互控件只保留为学习目标服务的项；为大屏提供显著的“教师演示 / 上一步 / 下一步 / 暂停 / 重置”，为学生操作提供可发现的提示。
- 默认中文界面，适配投影、希沃白板、鼠标和触摸；文字、线条、按钮与可点击区域在教室远处也应可读。
- 重要关系同时用位置、形状、文字、箭头或标签编码，不能仅靠红绿颜色区分。
- 完成前在浏览器中检查：首屏可见、画布尺寸正常、旋转/动画/时间轴/重置有效、关键帧与字幕同步、没有明显控制台错误。

如果用户只要“交给其他编程 Agent 的提示词”，先写清教学目标、模型结构、交互、课堂提问和验收标准，再输出可复制提示词；不把未授权的第三方代码、模型、截图、品牌或视觉样式伪装为 LX 原创。

## 课堂降级与交付

默认按“一块大屏 + 少量电脑 + 小组轮流”的场景设计：教师先用大屏演示，学生先预测并记录，再由小组操作与解释。为网络不稳定或没有人手一机的课堂提供：

- 一个离线可打开的 HTML；
- 一个简短的教师提问顺序；
- 一个不依赖设备的替代动作，例如纸质视图卡、部件卡、手势模拟或黑板箭头图。

交付时说明：适用学段、学习目标、使用方式、生成文件路径、教师可如何调整变量/文字，以及已作出的假设。不得把真实学生姓名、照片、成绩、隐私数据或班级排名写入成品。

## 安全与原创边界

- 化学、机械、电气或医学主题仅用于概念、结构和原理可视化；不提供危险实验、武器、车辆高速操作、高压/高温设备等可执行操作指引。
- 不自动安装 Python、Node、建模软件、三维渲染库或浏览器插件。若高精度 CAD、STEP/GLB 导出确有必要，先说明依赖、用途和替代方案并征得用户同意。
- 只能复制用户拥有权利或明确开放许可的模型、纹理、代码和音频。若用户给出一个未标注许可证的开源仓库，学习其高层教学思路并独立实现，不复制源码、模型、纹理或页面。
