# lx 手势互动教学

把学生的手变成 3D 世界里的“手”：直接抓、拉、推、旋转、拆开模型，或以力场吸引、驱散、重塑粒子；学科规律由这些可见动作呈现。最终不是一串网址、仓库链接、CDN 清单或提示词，而是一个实际存在、可打开的 `.html` 教学页面。

**严禁把摄像头手势降级为滑块、数字增减器、普通按钮或选择题的替代输入。** 读数、公式和图表可以同步出现，但只能是学生操控模型/粒子后看见的证据，不能是手势的主要操控对象。

**手势是第一设计驱动。** 先问“这一只手做什么才会让人想试”，再选择能被它操控的对象与教学关系；不是先做一套普通课件，再硬塞手势。若关闭 HUD 后看不出手造成了什么强烈、明确、好看的变化，或画面只发生细小/隐蔽/数字化变化，直接判定失败并重做。复杂度只服务于主动作：该简单时只保留一个动作，该复杂时也必须让每个动作都有肉眼可见的力量感和画面意义。

## 先判断是否该用手势

手势适合表达方向、大小、靠近/远离、展开/收拢、抓取/拖动、选择和停顿，且这些动作与要理解的变量或关系确实有关。若只是在展示答案、堆粒子特效，或学生不需要身体动作也能更清楚地理解，就不要强加摄像头交互。

| 用户真正需要的结果 | 优先 Skill |
| --- | --- |
| 一个主题的高质感单文件互动网页，未明确需要摄像头 | `lx-interactive-teaching-generator` |
| 摄像头手势要直接操控 3D 模型、粒子或教学过程 | **本 Skill** |
| 空间、传动、力和运动的慢速 3D 课堂演示，手势不是核心 | `lx-3d-teaching-animation` |
| 高中几何、圆锥曲线或化学反应的精确题解 | `lx-highschool-geometry-chemistry` |
| 游戏任务、关卡、奖励与整节课机制 | `lx-gamified-learning-design` |

手势版本沿用 `lx-interactive-teaching-generator` 的高质感单 HTML 标准，但它可以独立工作；不要假定用户已经安装了其他 LX Skill。

## 一个知识点即可启动

当用户只给出“太阳系”“欧姆定律”“一次函数”“细胞分裂”这类知识点时，**不要抛出一张十五项技术手势菜单**。先基于该知识点给出至多三个“主动作—主画面”卡片，让用户回复 A/B/C；每张卡只有一个简单、易做、能一眼看懂的主动作，例如“🤏 捏合拖动地球”“两根手指牵引飞行粒子”“🤏 撒下种子”。

用户回复一个选项后，围绕该动作做完整成品，不把它扩张成复杂体感系统。若用户说“按你推荐的直接生成”，选择一个最贴近概念的招牌动作即可；不为了显得功能多而再加开掌、握拳、拇指、挥手等一串手势。无论哪种模式，都默认教师大屏演示、摄像头关闭起步、鼠标/键盘替代、适合概念的电影感视觉世界、预测—操作—解释—迁移闭环。

## 补问真正影响设计的信息

先完整阅读用户已上传的教材、题目、教案、学情与设备说明，不重复索要。若用户没有直接指定手势，第一轮只发送主题专属的三张主动作卡；不要再额外追问。必要时用户选择后再补一个真正影响实现的问题。

```text
我会把【知识点】做成单文件手势互动教学 HTML。选一个你想要的主玩法：

A　[一个最直观的动作] → [直接操控的 3D 对象/粒子] → [最强的画面变化]
B　[另一个简单动作] → [直接操控的 3D 对象/粒子] → [最强的画面变化]
C　[第三个简单动作] → [直接操控的 3D 对象/粒子] → [最强的画面变化]

回复 A/B/C 即可；也可以说“按推荐直接做”。我只围绕一个主动作做，不会塞一堆难记手势。
```

主题专属主动作优先选 `🤏 捏合抓取/撒放`、`☝️ 两指或食指牵引`、`✋ 掌心力场`、`双手拉开/合拢` 中最适合的一种；详细的远近、方位、OK、V、拇指、挥手等只在用户主动提出或该动作确有不可替代价值时，才从 [gesture-menu.md](references/gesture-menu.md) 选择。手离镜头远近只表示经校准的相对距离，不能假称是准确厘米。

若用户已提供明确的手势、变量或课堂设备，跳过选择卡，直接使用这些信息。若缺失关键信息，最多再问三个问题：

1. 学段、学科、知识点，以及学生最后要能解释或完成什么？最容易误解哪一处？
2. 用户选择的**一个主动作**直接操控哪个**3D 对象/结构/粒子群**？抓、拉、推、旋转、拆解、聚拢、驱散或重塑后，学生要看见什么学科证据？
3. 用于教师大屏演示、学生轮流体验，还是个人练习？可否授权摄像头、是否有 Chrome/Edge 与稳定网络？

用户已经指定主题或要求直接生成时，作出合理默认：**一个招牌教学手势**、教师大屏模式、摄像头关闭起步、鼠标/键盘同等替代。不要用大量反问拖住成品。

## 视觉奇观是教学入口，不是可选装饰

普通白底课件、简单几何体加两个按钮、只有一条粒子线的页面均不合格。每个成品先选择一个与知识对象匹配的视觉世界，再让手势真正改变其中的学科关系。

至少同时具备：

1. **主视觉奇观**：首屏就能辨认的核心画面，如宇宙沙盘、全息实验室、分子星云、暗黑无限几何空间、立体方块世界；不用别人的品牌、角色、素材或界面。
2. **空间层次**：真实的 3D 主模型，以及至少两个能服务理解的层次，例如轨道/投影面/磁感线、粒子流/体积雾/扫描环、结构剖切/透明层/数据标注。不能用平面图标假装 3D。
3. **有力量的即时反馈**：手势首先抓、拉、推、旋转或扰动模型/粒子，模型运动、光线、粒子、读数与公式才从同一状态源同步变化；需有一个可录屏的高潮时刻，但不以随机烟花、换色或数字跳变取代概念变化。
4. **教学冻结点**：在视觉变化最明显处可暂停、显示预测问题和可见证据，再回到操作。学生看见的不只是“好看”，而是变化为什么发生。

先读 [visual-direction.md](references/visual-direction.md) 选择视觉方向与最低完成度；它提供“太阳系”等知识点的一句话启动默认，而不是要求用户先写美术需求。

## 选择交付方式

默认交付一个单文件 HTML，并在页面内放清楚模式切换；用户可以选下面任一方式：

- **摄像头课堂演示版（默认）**：点击“开启手势”后才申请权限；镜像小窗、识别状态、手势图例、暂停与重置齐全，适合希沃/投影大屏和学生轮流上台。
- **学生自主体验版**：先做 15 秒校准和单一手势练习，保留预测—操作—解释—验证节奏，不能用排名或手势熟练度给学生贴标签。
- **无摄像头替代版**：同一个 HTML 中用鼠标、触摸、键盘、按钮控制相同变量；它是摄像头不可用、学生不愿露脸、设备权限失败时的正式路径，不是阉割版。
- **开发提示词版**：仅当用户明确要求“给 Codex/Claude Code 的提示词”时才交付。否则直接写出 HTML 成品。

## 将手势翻译成直接操控与概念

先定义“学生的手要碰到什么”，再写变量和公式。一个基础关系通常只由一个稳定手势完成；不要让同一动作同时改电压、镜头、颜色和题目难度。完整阅读 [direct-manipulation-contract.md](references/direct-manipulation-contract.md)；若做不到模型/粒子的直接响应，就不要声称这是手势互动教学。

1. 先写下学习链：**预测什么 → 手直接碰/拉/推哪个对象或粒子 → 发生什么空间变化或物理过程 → 哪个读数/公式随之变化 → 怎样解释/迁移**。
2. 按用户从选择卡选定的动作设计**一个主控制**；主控制必须让 3D 对象或粒子在手势出现的瞬间响应。旋转、缩放、重置等非核心操作交给鼠标/按钮；不要把它们伪装为第二、第三个手势。只有教学上确有必要，才增加一个辅助动作。
3. 完整阅读 [hero-gesture-patterns.md](references/hero-gesture-patterns.md)，再读取 [gesture-concept-mapping.md](references/gesture-concept-mapping.md)。用户主动要求细节或自定义手势时才读取 [gesture-menu.md](references/gesture-menu.md)。不要照抄游戏项目里的“握拳换颜色”等纯视觉规则。
4. 每一次触发都要在屏幕上说明：识别到了什么、手正作用于哪个对象、对象/粒子怎样响应、由此出现了什么读数/状态、这支持或推翻了什么预测。

欧姆定律的合格例子：学生用捏合抓住悬浮的电阻线圈并把它拉长/压短，线圈在 3D 中真实伸缩，电子粒子在其中拥堵或加速，灯丝热辉光随之改变；再由安培表与 `I = V/R` 跟随显示结果。拇指上/下若被选中，必须推动 3D 电源核心/能量推杆并直接看见能量粒子注入或减弱，而不是只加减数字。张开手掌可冻结粒子流并要求预测。不要用“比个赞就答对”代替物理关系。

## 单文件实现契约

生成 HTML 前，完整读取 [single-html-contract.md](references/single-html-contract.md)。其中规定了摄像头权限、MediaPipe、手势防抖、隐私、性能、替代控制与验收要求。生成给其他 Agent 的开发提示词前，还要读取 [agent-prompt-blueprint.md](references/agent-prompt-blueprint.md)。

不可退让的规则：

1. 有文件写入能力时，直接在用户指定位置或当前工作目录创建一个命名清楚的 `.html` 文件；交付时报告路径。不得只给网址或未保存的代码片段。
2. 手势开启后，用户选择的每个动作必须直接作用于可见 3D 模型/粒子，不得只更新 HTML 数字、滑块、按钮状态、题目或镜头。至少一个对象应有“抓取/力场/约束轨道/可拆解结构”中的直接操控感。
3. 页面从“摄像头关闭”开始；只能由用户点击明显的“开启手势/摄像头”按钮触发 `getUserMedia`，并提供“关闭摄像头”按钮来停止所有 video tracks。
4. 摄像头画面、手部关键点与控制状态只在本页面运行时使用；不上传、录制、存储或作为学习评价。页面仍可能从公开 CDN 下载 Three.js、MediaPipe 运行时和模型，须在页面说明这一点。
5. 摄像头通常需要 HTTPS 或 `localhost` 才能授权。HTML 本身仍是唯一交付物；页面需在无法授权、浏览器不支持或网络失败时自动显示原因并切换到鼠标/键盘模式，不能变成打不开的黑屏。
6. 默认使用 MediaPipe Tasks Vision 的 `HandLandmarker` 或 `GestureRecognizer`，读取 21 个手部关键点；3D 用 Three.js，2D 用 Canvas/SVG。不要依赖本地服务器、私有 API、账号、构建步骤或多个本地文件。模块与 Wasm 的 URL 必须采用 [single-html-contract.md](references/single-html-contract.md) 中已校验的固定地址；禁止编造包版本、漏写 `cdn.`，或把中文状态文案拼进动态 import URL。
7. 手势识别必须平滑、去抖和有冷却：关键点使用指数平滑；阈值按掌宽归一；连续识别稳定一小段时间才触发离散命令；切换类手势有冷却时间；每一帧可实时更新的连续变量与一次性命令分开处理。
8. 页面有“识别中/未检测到手/光线不足或手出框/已暂停/鼠标替代”状态，不声称识别一定准确。重要学习变量不可只靠颜色传达。

## 教学与安全底线

- 手势用于理解，不用于羞辱、公开排名、体能筛选或强迫学生出镜。始终保留键盘、按钮和教师代操作，照顾行动受限、摄像头不可用或不愿使用摄像头的学生。
- 小学生优先使用直观、易保持、低疲劳手势；连续举手或复杂手型不能成为完成任务的前提。
- 页面至少有：学习目标、手势教学卡、核心可操作模型、预测提示、即时读数/反馈、解释/迁移出口、重置与无摄像头替代。
- 化学、电路、机械等只可视化概念和安全范围内的模型；不提供可操作的危险实验、高压或高温设备参数。
- 不嵌入真实学生照片、姓名、音视频或人脸数据；不把摄像头画面传给外部 AI 服务。

## 完成前检查

交付前实际检查生成的 HTML：

- 鼠标/键盘替代控制能完成与手势相同的教学变量变化；
- “开启手势”前不申请摄像头；拒绝权限后仍可操作；关闭后 tracks 停止；
- 用户选择的每个手势都有独立识别、明确 HUD 和实际模型/粒子响应；手势抖动、短暂遮挡、两手靠近和无手状态不会连续误触发；
- 核心模型、数值、公式、视觉反馈和解释来自同一状态源；
- 首屏就能看出明确的视觉世界；核心对象有真实空间层次、光影/粒子/后期中的适量组合，且大屏文字仍可读；
- 重置、暂停和重新校准有效；
- 页面真实服务一个概念关系，不是用手势触发选择题、数字滑块或换皮特效。

## 提示词结构与来源

高质量的手势网页提示词必须把“角色/交付格式—教学目标—视觉世界—变量与手势映射—识别稳健性—权限/隐私—替代控制—验收”逐层写清。按需读取 [agent-prompt-blueprint.md](references/agent-prompt-blueprint.md) 来生成给其他编程 Agent 的提示词。

本 Skill 只吸收公开项目的高层交互思路：MediaPipe 的 21 点手部追踪、捏合/双手缩放的连续控制、手势到视觉对象的可读反馈、粒子/3D 的性能与状态设计。它不复制 PixelPalm、ULTRON、NEURAL HAND 或其他上游项目的源码、素材、品牌、角色设定或未明确许可的提示词。来源与许可判断见 [research-notes.md](references/research-notes.md)。
