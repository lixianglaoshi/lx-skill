# 给编程 Agent 的手势教学网页提示词蓝图

只有用户明确要求“开发提示词”时使用。把方括号替换成经用户确认的内容；不要原样输出仍带占位符的提示词。

```text
你是一名兼具 Three.js、MediaPipe Tasks Vision、交互设计与学科教学经验的前端工程师。

请直接在当前工作目录交付一个名为 [文件名].html 的单文件教学网页。不要只给链接、仓库地址、代码片段、构建步骤或多文件项目。HTML 内联 CSS 与业务 JavaScript；页面必须在没有摄像头权限时仍可通过鼠标、触摸、键盘和按钮完整体验。

【学习目标】
- 学段/学科：[...]
- 核心关系：[...]
- 学生常见误解：[...]
- 学生要做的证据性动作：[预测 → 操作 → 观察 → 解释 → 迁移]

【视觉与模型】
- 先选择一个匹配知识对象的电影感视觉世界：[宇宙沙盘/全息实验舱/微观星云/无限几何空间/立体方块世界/其他]。不要生成白底课件、普通控制面板或悬浮在中央的简单球体。
- 核心模型：[真实的 3D/2D 对象与变量]。需要真实空间关系的主题，必须使用真实 Three.js 3D 对象、可旋转镜头、光影和前后遮挡，不能用平面图假装 3D。
- 至少搭建三层：主模型、解释关系的结构层（轨道/磁感线/投影面/分子键/波场等）、环境或数据层（粒子、扫描环、雾气、读数）。全部由程序生成或明确可用的开源素材构成；不得照搬已有项目的品牌、角色、界面或素材。
- 手势必须先直接抓、拉、推、旋转、拆开模型，或用力场吸引、驱散、重塑粒子；模型运动、光线、粒子、读数和公式才从同一状态源同步变化，并设计一个可录屏的“视觉高潮”。它必须对应学科变化，不能只是随机爆炸、换色、烟花或数字跳变。
- 在高潮处设计暂停与预测问题，让学生从视觉证据回到解释。大屏文字必须高对比、可读；提供高对比投影模式和减少动效选项。

【手势—变量映射】
围绕用户明确选择的**一个主动作**完成全页，不得为了显得功能多堆叠十种手势：
1. [主手势] → 直接抓/拉/推/旋转/拆解的 [3D 对象或粒子群] → [立刻可见的空间/粒子反应] → [随后同步的读数/公式证据]。
2. [可选的一个辅助动作，仅在教学上不可替代时加入] → [...]
镜头旋转、缩放、重置优先使用鼠标、触摸或按钮，不要伪装成第二、第三个教学手势。

手势的主输出必须是模型与粒子反应，绝不允许直接给 HTML 数字加减、操作滑块、点击按钮或跳转题目。对每个主手势实现手—物绑定：跟手的抓取环/射线/能量束/力场、对象在允许约束下的变换或粒子速度场变化，以及由同一状态派生的 HUD。关闭 HUD 后，仍能从画面看懂手操控了什么。

【手势追踪】
- 使用官方 MediaPipe Tasks Vision 的 HandLandmarker（最多 [1/2] 只手），Three.js 渲染 [3D 模型/粒子]。
- 使用以下**固定常量**，不得自行猜测版本、改写域名或在 URL 后拼接状态文本：
  ```js
  const MEDIAPIPE_MODULE_URL = "https://cdn.jsdelivr.net/npm/@mediapipe/tasks-vision@1.0.1/vision_bundle.mjs";
  const MEDIAPIPE_WASM_ROOT = "https://cdn.jsdelivr.net/npm/@mediapipe/tasks-vision@1.0.1/wasm";
  const HAND_LANDMARKER_MODEL_URL = "https://storage.googleapis.com/mediapipe-models/hand_landmarker/hand_landmarker/float16/1/hand_landmarker.task";
  ```
- 点“开启手势”后按“加载模块 → 初始化 Wasm/模型 → 请求摄像头 → 追踪”顺序执行；`await import(MEDIAPIPE_MODULE_URL)` 必须 `try/catch`。加载失败时显示中文可读错误、继续使用鼠标/键盘按钮和可展开诊断；不能显示一整条失败 URL，更不能在引擎未加载成功前打开摄像头。
- 首屏摄像头关闭；只在用户点“开启手势”后申请 video 权限；必须有“关闭摄像头”并停止 tracks。
- 使用基于掌宽归一化的阈值、指数平滑、200–350ms 稳定确认、500–800ms 冷却；显示“识别中/无手/当前手势”。
- 明确镜像坐标，摄像头画面只本地使用：不录制、不上传、不保存。
- 摄像头通常需要 HTTPS 或 localhost；若权限拒绝、无设备、外链模型失败或直接打开文件时不可用，自动进入替代控制且解释原因。

【替代控制】
- 为每个模型抓取、力场、拆解、旋转或粒子操作提供鼠标、触摸、键盘等价交互；这些不是隐藏的调试入口，而是正式可用路径。替代控制可以改变同一模型状态，但不能反过来把摄像头手势设计成数字滑块。

【教学界面】
- 有学习目标、手势教学卡、变量/单位/公式 HUD、先预测后验证、可折叠检查、暂停、重置、重新校准、纸笔/口头迁移任务。
- 首屏有低干扰、可折叠的“主动作教学卡”，只显示一个主手势、直接操控的对象/粒子、随后出现的学科证据、实时识别状态和等价鼠标/键盘控制；没有实现的手势不得出现在教学卡中。
- 默认适配教师投影 + 小组轮流；不能把手势熟练度作为排名或评价。

【验收】
- 交付前实际检查 HTML：无需手势也可完整体验；开关摄像头、拒绝权限、无手、短暂抖动均不会卡死或连续误触发；同一状态源同步模型、粒子、数值、公式和文字解释。关闭全部 HUD 后，从前五秒画面也必须能看出手抓住/牵引/扰动了什么；否则返工。
- 验收视觉：首屏三秒内能看出独特的视觉世界；真实的 3D 学科对象有可辨认的深度/遮挡/层次；关键手势有一处强烈但不遮蔽知识证据的视觉反馈；不得只交付普通课件式 UI。
- 最终回复只报告已生成的 HTML 文件路径和极短的使用前提。
```

## 为什么这样写

按“交付物 → 学习目标 → 视觉模型 → 手势语义 → 追踪稳健性 → 权限与替代 → 验收”排序。这样编程 Agent 不会只生成一个粒子特效，或只贴 CDN/在线预览链接，而能把手势、学科变量与文件交付绑在一起。
