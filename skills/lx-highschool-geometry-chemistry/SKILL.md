# lx 高中几何 + 化学反应

为高中具体题目交付一个可以直接打开和操作的 `.html` 网页。题面、计算、分步讲解、图形/模型和最终答案必须来自同一份精确数据；绝不只交一串网址、仓库链接或“你再去找别的 AI”的指令。

## 选择模式

| 用户的题目或目标 | 读取并使用 |
| --- | --- |
| 空间几何体、线面角、二面角、距离、体积、向量/法向量 | `vendor/edulab/edu-solid-geometry/SKILL.md` |
| 椭圆、双曲线、抛物线、圆、动点/动直线、范围、定点/定值、轨迹 | `vendor/edulab/edu-analytic-geometry/SKILL.md` |
| 配平、原子守恒、氧化还原、断键/成键、反应机理、微观分子动画 | `vendor/edulab/edu-chem-reaction/SKILL.md` |

如果用户只是说“做一个炫酷的教学网页”或主题不属于上述三类，转用 `lx-interactive-teaching-generator`。如果用户要设计整节游戏化课，转用 `lx-gamified-learning-design`。

## 不可退让的交付规则

1. 最终成品是**一个实际存在的 `.html` 文件**。有文件写入能力时，写到用户指定位置；未指定时写到当前工作目录。交付时给出文件路径，不用网址替代成品。
2. 不得把 GitHub、在线编辑器、CDN 地址、代码片段、多个 `.py` 文件或命令列表当作最终交付。构建脚本、预览截图、缓存和临时文件只能在临时位置；交付目录只新增这个 HTML 成品。
3. 成品不依赖本地服务器、私有 API、账号登录或用户手动拼接多个文件。稳定 CDN 可以增强展示；用户要求离线时，必须改用内联资源或明确可运行的简化替代，不能交付打不开的空壳。
4. 计算必须由对应上游模块的 SymPy kernel 驱动：禁止凭心算或凭图猜出答案，再把不一致的数据塞进动画。图片题先回显识别出的题面、条件和所求并请求确认。
5. 先检查 `sympy` 是否可用。若缺失，先征得用户同意才安装或切换解释器；不得自动安装 `sympy`、RDKit 或其他依赖。化学内容仅做概念与微观可视化，不提供危险实验操作细节。

## 统一教学要求

- 页面要让学生做一个真实的认知动作：旋转并指认关键线面、拖动参数观察不变量、拉动反应进度看原子重组，随后解释和验证。
- 至少包含：题面/现象、可操作模型、分步推导、即时读数或反馈、一个预测/验证动作、最终答案，以及一道迁移提问或纸笔表达出口。
- 立体几何使用真实 Three.js 3D 模型；解析几何使用可拖动的 2D Canvas/SVG 画板；化学反应使用真实可旋转的 3D 分子模型。不要把互动退化为“点一下显示答案”。
- 生成后检查：HTML 可在浏览器直接打开，控件确实改变模型，答案卡、最后一步、公式与动态读数一致；若启动本地预览服务，检查完立即关闭。

## 上游模块的使用顺序

在选择模式后，完整读取对应 `vendor/edulab/.../SKILL.md`，再按其要求读取所需 `references/`、调用 kernel 与 `scripts/generate.py`。上游三套模块的“唯一最终产物为当前工作目录中的单个 HTML”“依赖征求同意”“图片先确认”“精确结果同源”等规则在本 Skill 中均为强制规则。
